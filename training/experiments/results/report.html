xG Match Companion · model experiment

Boosting vs Bagging

We put bagging, XGBoost, a random forest and a tuned LightGBM up against the shipped model on 4,988 held-out shots. None clearly beats it. The one real gain is about 0.003 in log loss, on full-detail inputs only.

What we found

  • Bagging did not help.The model is already gradient boosting, and each tree already sees a random 80% of shots and features. Averaging five LightGBM models scored 0.2627 against 0.2630 shipped, no better than the average single model (0.2626). Bagging by resampling whole matches scored 0.2631 with a clearly worse Brier score (+0.0007).
  • XGBoost and a random forest were no better, and the forest is far heavier.XGBoost scored 0.2688 (+0.0059 vs shipped, interval −0.0002 to +0.0142) with a slightly lower AUC (0.8041 vs 0.8051). The random forest scored 0.2652, a clearly worse Brier score, a weaker match to StatsBomb’s own xG (0.884 vs 0.905), and 38 times as many tree nodes (433,826 vs 11,536), which would swell the offline download.
  • Most gaps are smaller than re-rolling the random seed.Retraining the shipped configuration with ten different seeds moves full-input log loss by a standard deviation of 0.0030 and a spread of 0.0095. Every full-input difference in the first comparison is smaller than that spread.
  • The one real signal: a tuned LightGBM, about 0.003 better.The grid picked 15 leaves and depth 6 (shipped: 31 leaves, depth 5). Averaged over ten seeds each it scored 0.2606 vs 0.2636 on full inputs, 0.0030 better, interval −0.0060 to −0.0006. On partial and minimal inputs it made no difference. The single-seed comparison had shown −0.0049, so part of that was luck. It is also 14% smaller.
  • With minimal input, the algorithm does not matter.All six models land within 0.0005 of each other (0.2672 to 0.2677). That ceiling comes from how little the operator entered, not from which tree method reads it.
  • Recommendation: keep the shipped model for now.A 1% log-loss gain in one input level does not justify retraining, since every xG number would shift slightly and the ONNX file, calibrators and parity fixtures would all be regenerated. If the model is retrained anyway, for example with more data, adopt the tuned configuration then and judge changes with multi-seed comparisons like this one.

One follow-up: is the tuned LightGBM really better?

In the first run the tuned model looked about 0.005 better, roughly the size of one model’s seed-to-seed range, so luck of the seed could explain it. Each configuration was retrained with 10 different seeds and compared on average.

Tuning grids

Every configuration tried, scored on the validation set only (calibrators fit on the calibration split). The test set was not used to pick any configuration.

How it was run

  • Same protocol as the shipped model. Match-level split, the same augmented training set (feature-group dropout and jitter), the same early-stopping set, the same per-bucket isotonic calibration on calibration ∪ validation. The refit of the shipped configuration reproduces the shipped model exactly (maximum prediction difference , same best iteration).
  • Bagging, two ways. Seed-averaging (five LightGBM models differing only in seed) and match-bootstrap bagging (five models, each trained on a resample of whole training matches). Probabilities are averaged, then calibrated as one model. A random forest is the classic bagging of deep trees.
  • Monotone constraints (distance, angle, defenders, and so on) are kept for LightGBM and XGBoost. The random forest ran unconstrained: scikit-learn does not support monotone constraints together with missing values, and missing values are how this model represents “not entered”.
  • Uncertainty. Paired cluster bootstrap, 4,000 resamples of the test matches.
  • Known limits. The validation set that picks each grid winner is also the set the boosted models early-stop on, which flatters all boosted models a little (the forest has no early stopping). The test set was looked at twice: once for the six-model comparison and once for the 10-seed follow-up on the config that grid picked. One split, one test set of 456 goals.
  • Not tried: CatBoost, stacking, feature changes, tuning beyond the small grids above, and a second random split.
