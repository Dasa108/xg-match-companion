One follow-up: is the tuned LightGBM really better?

In the first run the tuned model looked about 0.005 better, roughly the size of one model’s seed-to-seed range, so luck of the seed could explain it. Each configuration was retrained with 10 different seeds and compared on average.

Tuning grids

Every configuration tried, scored on the validation set only (calibrators fit on the calibration split). The test set was not used to pick any configuration.

How it was run

  • Same protocol as the shipped model. Match-level split, the same augmented training set (feature-group dropout and jitter), the same early-stopping set, the same per-bucket isotonic calibration on calibration ∪ validation. The refit of the shipped configuration reproduces the shipped model exactly (maximum prediction difference , same best iteration).
  • Bagging, two ways. Seed-averaging (five LightGBM models differing only in seed) and match-bootstrap bagging (five models, each trained on a resample of whole training matches). Probabilities are averaged, then calibrated as one model. A random forest is the classic bagging of deep trees.
  • Monotone constraints (distance, angle, defenders, and so on) are kept for LightGBM and XGBoost. The random forest ran unconstrained: scikit-learn does not support monotone constraints together with missing values, and missing values are how this model represents “not entered”.
  • Uncertainty. Paired cluster bootstrap, 4,000 resamples of the test matches.
  • Known limits. The validation set that picks each grid winner is also the set the boosted models early-stop on, which flatters all boosted models a little (the forest has no early stopping). The test set was looked at twice: once for the six-model comparison and once for the 10-seed follow-up on the config that grid picked. One split, one test set of 456 goals.
  • Not tried: CatBoost, stacking, feature changes, tuning beyond the small grids above, and a second random split.
